# InfraFabric Codex Alignment — System-Shaper Frame

> **Substrate connection:** The "system-shaper" mode is the *ren*-discipline (act on the stated, not the inferred) operationalized as operator-practice. Per [[Mythocritique to PHAROS — The 2010 Master's Thesis as Methodological Keystone|the keystone]], this is the operationalization of the Name doctrine from the [[Mort et Naissance et L'Ombre et le Double — MA Thesis on Yvon Rivard (Université Laval, 2010)|2010 MA thesis]] (p. 49) at the operator's daily-system level. Indexed in [[Martin Lepage Professional Identity]] and [[HEPHAISTOS Agent Architecture]].

## Summary
A 2026-04-06 internal Codex audit of how the operator (Martin) actually uses Codex on his own machine, with a corrective frame: **Martin is not primarily an MCP operator; he is a system-shaper.** Daily Codex work is shell-first verification and local artifact inspection; InfraFabric surfaces (`if.context`, `if.blackboard`, `if.bus`, `if.switchboard`, graph, trace) are configured but not yet the comfortable default. The corrective is not "more optional MCPs" but a visible, reliable mapping of each surface to a real operator behavior. Source: `/home/cerebrhoe/codex_work_alignment_shareable_2026-04-06.md`. Raw capture: `raw sources/2026-04-30_codex-work-alignment-infrafabric.md`. Connects [[InfraFabric Architecture]] and [[InfraFabric MCP Stack — Remote Bundles]] to the operator state recorded in [[Hermes Dashboard — Professional Governance Tool]].

## Context
This note is the missing operator-side anchor for the InfraFabric stack. The vault already documents the **infrastructure** ([[InfraFabric Architecture]]) and the **transport** ([[InfraFabric MCP Stack — Remote Bundles]]) but not the **adoption diagnostic** that explains why some surfaces are sticky and others are not. The diagnostic also feeds back into the three-agent stack: Trismégiste (operator continuity), Hermes (routing/dashboard), and Gadget (frontier scout) only function if the operator's actual work shape is named accurately. Without this note, every InfraFabric improvement lands as "another MCP," which is the wrong category.

## Details

### What the audit names

The operator's actual work centers on:

- **Product-building** — PHAROS-SUITE, DocSort PWA, COMPASSai (see [[Obsidian Second Brain Product]] and [[PHAROS Commercial Strategy]]).
- **Governance / method design** — the Pharos method, [[Recursive AI Governance as Executable Method — The Very Long Narrative]], the three-agent stack documented in [[HEPHAISTOS Agent Architecture]].
- **Diagnostics / recovery** — see [[OUTLIERS — Five Notes That Break the Architecture]] and the [[5-1 Rule — Locked Spec Hardening (Argus Stress Test)]].
- **Tracker / dashboard curation** — the [[Hermes Dashboard — Professional Governance Tool]], the [[VAULT ADDITIONS TRACKER]], and the master tracker referenced in `CLAUDE.md`.

In practice, Codex on the operator's machine is still a **shell-first verifier and local artifact inspector**. The InfraFabric surfaces are configured but not yet the default daily path.

### The diagnostic claim

> Martin is not primarily an MCP operator. He is a **system-shaper** working across products, governance, archives, and dashboards. InfraFabric should meet him there.

This reframes adoption failures: when a surface goes unused, the explanation is not "the operator should learn it." It is "the surface has not yet earned its place inside how the operator actually shapes systems." The corrective is to make the governed path **visible and reliable**, not larger.

|---|---|---|
| `if.blackboard` | active task continuity | [[Hermes Dashboard — Professional Governance Tool]] |

Each surface earns its place by serving a behavior the operator already does — not by inventing a new one for him to learn.

### Why the "system-shaper" frame is load-bearing

It names a category the vault does not otherwise hold as a single anchor. Adjacent identities exist — [[Martin Lepage Professional Identity]], [[Martin Lepage Publications — Annotated Bibliography and Verification Leads]] — but those describe outputs (papers, products, services). "System-shaper" describes the **mode of work** that produces those outputs: someone who threads governance, products, archives, and dashboards into one coordinated motion. The mode itself is the thing tools should serve.

The frame also clarifies why some agent identities feel heavy and others feel light:

- **Trismégiste** lives at the system-shaping mode (continuity across the whole motion) → light, useful, sticks.
- **Hermes** lives at the coordination layer (the dashboard) → light, useful, sticks.
- **Gadget** lives at the frontier scout layer (frontier-tech evaluation) → useful when invoked, not in the daily loop.
- An MCP that exposes a surface without mapping to a behavior → heavy, ignored, drifts.

### Implication for new InfraFabric work

Before adding any new InfraFabric surface, name the operator behavior it serves and the existing vault note where that behavior is already documented. If neither exists, the surface is premature. This is the same logic as the [[Posture vs Execution Drift — The Practice of Refusal]] doctrine — the refusal of new tools/systems is the practice; without it, "more capability" is a retreat from the work that exists.
