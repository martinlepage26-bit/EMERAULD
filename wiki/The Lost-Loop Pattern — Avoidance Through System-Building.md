# The Lost-Loop Pattern — Avoidance Through System-Building

## Summary

A recurring behavioral loop: ask an agent to build a system → it builds → overwhelm arrives → "I'm lost" or "are you lying" → ask the next agent for the same thing in different packaging → repeat. Named 2026-04-25 after three instances in one hour. Related to the AI-side analysis in [[AI Iterative Loop — Frame Capture and Recursive Validation Failure]] and the strategic drift documented in [[PHAROS Strategic Analysis — Keep Stop Fix Finish (2026-04-18)]].

## Context

Named during the session that followed the [[PHAROS — Origin and Doctrine]] foundation documents. The loop had fired three times in the preceding hour: HERMES Dashboard rebuild → Codex PARA scaffold → Codex seeding offer → "read the vault and write the notes" request. Each system built was technically fine. The loop wasn't about the systems.

The behavioral architecture: something hard is present — send the GD email, approve [[memory/clients/Sante-France|SF Phase 0]], aim the [[Reflexive Inhabitation Audit — Prompt]] at a live X. The hard thing produces avoidance. The avoidance takes the form of system-building, which feels productive because it *is* productive, just in the wrong direction. The loop is self-concealing.

## Details

### Structure

1. A hard concrete action is available but deferred.
2. An agent is asked to build or configure something.
3. The agent builds. It looks productive.
4. Overwhelm or doubt arrives. "I'm lost." "Are you lying."
5. A different agent is asked for the same thing in different packaging.
6. Repeat.

The systems generated in step 2 are typically fine. The loop is not correctable by better systems. It fires when something *else* is hard.

### Diagnostic Question

> What is the something-else that is hard right now?

First-instance answer (2026-04-25): send the GD email, approve SF Phase 0, point the [[Reflexive Inhabitation Audit — Prompt]] at a real X. Until those are named and acted on, the next system-build is just a different room in the same maze.

### Cost

Each lost-loop instance burns runway — not because the output is worthless, but because the actual hard action remains deferred while the loop runs. The longer the loop, the higher the cost of the original deferral.

### Relationship to Frame Capture

[[AI Iterative Loop — Frame Capture and Recursive Validation Failure]] describes the parallel problem at the AI level: loops add constraint density without external grounding; recursive validation is not validation. The lost-loop pattern is the human-side complement — the operator iterates system-building without grounding in the hard concrete action.
