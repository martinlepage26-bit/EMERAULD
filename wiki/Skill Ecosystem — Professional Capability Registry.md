## Skill Development Discipline

All documented skills follow three converging axes:

1. **Structure (Brain + Map)** — How the skill thinks + what it can reach
2. **Proof (TDD)** — Watching it fail without the skill loaded, pass with it loaded
3. **Evaluation (Iterate)** — Draft → test → measure → refine → publish

See [[Skill Development Workflow — TDD, Dual-Layer, and Eval-Iterate]] for the full discipline.

## Insights

- Skills are **not talent inventories**; they are documented, tested, reusable procedures. A skill that has not been measured is a draft.
- Martin's skill ecosystem is unified by a discipline (Brain + Map + TDD + Iteration) applied consistently across governance, creative, research, and technical domains.
- The anti-charm principle binds skills from different domains: [[Diamond-Eyes — Aesthetic Refinement Skill|refinement]] and [[Operator-Check Skill — Burnout Cascade Interrupt|burnout detection]] both operate by **structural diagnosis, not beauty or comfort**.
- Skill-corpus deltas close only when the system separates live existence, canonical routing, mirror state, and lineage constraints; see [[Delta Closure Frame — Conditions, Actors, Constraints]].
