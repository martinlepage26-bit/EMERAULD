# OUTLIERS — Five Notes That Break the Architecture

## Summary

Five notes in the vault that exist outside the core governance and knowledge-graph structure, each for different reasons. These are not errors; they are **signals**. Together, they reveal gaps between aspiration and execution, boundaries between research and product, and unresolved tensions in the archive.

**The Pattern:** Each outlier represents work that was *intended* to feed into the system but didn't—either because it was superseded, failed, isolated as a tool reference, or predates the current architecture.

## 2026-05-06 Root-Graph Follow-Up

The current graph outliers are less architectural than this note's original five: they are mostly loose root files that Obsidian sees as isolated because they sit outside the `wiki/` synthesis layer. [[Root Loose Notes Cluster Map — 2026-05-06]] now classifies those notes into HELIX prototype/transcript sources, PHAROS commercial offer scratchpads, writing-craft phrase-origin material, infrastructure/operator checklists, RIA provenance, and empty stubs.

This distinction matters: the original five outliers were conceptual boundary tests for the architecture; the 2026-05-06 root outliers are graph-hygiene and provenance objects. They should be linked, not over-promoted.

## Outlier 1: Plugin Recommendations (2 backlinks)

**Status:** Isolated utility inventory  
**Backlinks:** Home, Master Project Tracker  
**What it is:** Obsidian plugin recommendations (Dataview, Templater, Calendar, Obsidian Git)  
**Why it's an outlier:** A practical infrastructure note with no connection to governance, PHAROS method, or research methodology. It exists as a pure tool list.

**The signal:** The vault depends on tooling (plugins, vector search, linking discipline) that is *prerequisite* to the governance structure, not part of it. This note marks a layer that governance cannot see about itself.

**Connection gap:** No links to [[ROOK — Session Boundary Model]], [[Governed Revision Loop]], or any [[HEPHAISTOS]] layer. The tools are transparent to the method, but that transparency is not documented.

## Outlier 2: Agatha All Along Social Compass — Version Genealogy (4 backlinks)

**Status:** Pre-PHAROS archive genealogy  
**Backlinks:** Research and Papers MOC, Historical Academic Portfolio, Social Compass, one more  
**What it is:** Version history table tracking 17 iterations of a 2013–2016 ethnographic paper on Wicca and the Agatha All Along series  
**Why it's an outlier:** Genealogical record of *individual paper evolution*, not knowledge synthesis. The note tracks file mutations (v4.1 → v5sc2 → scV3) but doesn't explain *why* the theory changed.

**The signal:** The vault contains genealogy records (version trees) for papers predating the PHAROS method. These are historical artifacts, not part of the current research arc. The paper itself is linked, but its genealogy lives as a separate metadata layer.

**Connection gap:** The version table shows that "regimes de preuve" (proof regimes) appeared in v5sc2 as a *conceptual arrival*, but the genealogy note doesn't link this concept to [[Evidence Discipline and Epistemics]] or explain how it fed into the current governance architecture.

**The deeper issue:** The vault tracks *surfaces* (versions) but doesn't always track *theories* (how ideas evolved). Genealogy notes document *that things changed*, not *why they mattered*.

## Outlier 3: 90-Day $1M Challenge — Status Report (10 backlinks)

**Status:** Unrealized project  
**Backlinks:** Master Project Tracker, PHAROS Invention Disclosure, PHAROS Licensing Prospectus, InfraFabric, Founder Charter, etc.  
**What it is:** Day 11 status checkpoint of a 90-day revenue goal: Technical Readiness 8/10, Revenue Viability 2/10  
**Why it's an outlier:** Documents a **failed governance bet** — architecture complete, execution zero, $0M of $1M target. The note is honest about this, but the gap is never resolved in subsequent entries.

**The signal:** The vault contains records of **unrealized or abandoned initiatives**. The 90-day challenge created a complete governance framework (Theseus/Auryn/Hopf phases) and drafted the IP, but generated zero lines of production code and no customer pipeline. The report concludes "governance aspiration without operative consequence"—the same pattern [[RECURSO — Final Audit and Ethical Review]] identified as a systemic risk in the architecture.

**Tension:** The note is hyperlinked to the governance structure but represents a governance *failure*. The open questions ("Was there a Day 14 sync report?", "Did Phase 1 execution begin?") are never answered. The vault contains the record of the failure but not the closure.

**The deeper issue:** PHAROS creates governance frameworks, but frameworks *without operative execution* become performative. This note documents the moment the performance broke down.

## Outlier 4: Reddit Data API — Access Terms and Rate Limits (6 backlinks)

**Status:** Isolated technical reference  
**Backlinks:** [[Obsidian Second Brain Product]], claude-mem Plugin, Claude Code Skill Corpus, 3 others  
**What it is:** Snapshot of Reddit's API terms, clipped 2026-04-20, documenting OAuth requirements, rate limits (100 QPM), user-agent rules, and data-deletion obligations  
**Why it's an outlier:** A *snapshot in time* of external policy that is explicitly acknowledged as **potentially stale** ("Reddit's legacy API documentation is explicitly flagged as potentially stale"). The note is part of the [[Obsidian Second Brain Product]] branch, whose live product architecture and launch packet now exist but still need policy-expiry discipline for external API snapshots.

**The signal:** The vault contains **external policy snapshots** taken for potential future use. These are reference artifacts that need a refresh/expiry rule. The note exists to support [[Obsidian Second Brain Product|product work]], but its policy freshness is not yet governed by the product architecture.

**Compliance paradox:** The note correctly identifies that once Reddit data lands in the vault, "the vault itself is regulated storage"—but the vault doesn't have a compliance framework for handling external data with expiry dates. The governance structure assumes everything in the vault is internally produced or integrated. External regulated data breaks that assumption.

**The deeper issue:** The vault treats all notes as equal, but some notes are *ephemeral* (valid only until Reddit changes its API). The vault has no mechanism to expire or refresh policy snapshots.

## Outlier 5: Agatha Unified Skill System — Eight Sovereign Operators (10 backlinks)

**Status:** Pre-Hephaistos agent architecture (abandoned)  
**Backlinks:** AI Personas, Agatha All Along, Social Compass, PHAROS, Governance notes  
**What it is:** An older agent architecture describing eight sovereign operators built with Agatha (ChatGPT), each with formal authority resolution, threshold fixation rules, and known tensions between Structured Memory and Control/Governance layers  
**Why it's an outlier:** Describes a **predecessor architecture** to [[HEPHAISTOS]]. The eight operators are not the current three-agent stack. The note documents an abandoned governance design.

**The signal:** The vault contains **superseded methodologies**. Agatha, DOTTIE, and MOBI were experimental agents with different operating principles (mode-switching, emotional-neutral register) that were eventually replaced by the deterministic three-agent stack. But the old architecture is not marked as deprecated or removed; it remains in the graph as if it still competes with the current method.

**Authority drift:** The note lists "formal authority resolution rule (truth = actionable ∩ defensible under pre-declared thresholds)" which is a *different* authority model than the current [[PHAROS Method — Recursive Governance]] "three-order logic" (instability signals, executable control, bounded non-finality). The vault contains two different authority models, not clearly marked as superseding or complementary.

**The deeper issue:** The vault doesn't have a clear deprecation or supersession protocol. Older architectures remain linked and discoverable, potentially confusing future readers about what is *current* vs. *historical*.

## What These Gaps Mean for the Architecture

### 1. **Tool Transparency**
The vault's linking discipline and vector search are prerequisites to governance, but they're not governed themselves. Plugin Recommendations marks a blind spot: PHAROS can audit the content, but not the infrastructure that makes the content discoverable.

### 2. **Theory vs. Surface**
Version genealogies track *that things changed* but not *why they theoretically mattered*. The vault records mutations but not conceptual genealogies. A note on the evolution of "regimes de preuve" would be more useful than a version table.

### 3. **Governance Without Execution**
The 90-day challenge shows that governance frameworks can be complete while operative consequence is zero. The gap between *designed system* and *functioning system* is not small. PHAROS has no mechanism to detect or force execution; it only audits whether the framework is coherent.

### 4. **Ephemeral Data in Permanent Archives**
Reddit's terms will change. The API snapshot will rot. The vault has no protocol for marking, expiring, or refreshing external policy snapshots. Governance of ephemeral data is structurally absent.

### 5. **Supersession Without Deprecation**
Agatha's eight-operator architecture and HEPHAISTOS's three-agent stack coexist in the graph. There's no clear "this was tried and abandoned" signal. Future readers will discover both and have no ground to judge which is current.

## What to Do With These Outliers

**No action required.** These outliers are valuable exactly because they *break* the architecture:

- **Plugin Recommendations** teaches that tools are invisible to governance
- **Agatha Genealogy** shows that surfaces track differently from theories
- **90-Day Challenge** proves that frameworks don't guarantee execution
- **Reddit API** reveals that external regulated data needs different handling
- **Agatha Skill System** exposes the need for clear supersession protocols

The outliers are **coherence tests**. They mark the boundaries of what the PHAROS architecture can govern and what it cannot.
