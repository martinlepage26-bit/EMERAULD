# SECOND BRAIN ASSESSMENT

## Assessment summary

EMERAULD is functioning as a **hybrid vault**, not a pure second-brain notebook set. It already contains a real durable knowledge system, but that system is competing with operational mirrors, generated artifacts, raw intake packs, and embedded project runtimes. The result is not collapse. The result is **retrieval distortion**.

## What is working

### Verified strengths

- `Areas/`, `Resources/`, and key `memory/` notes already form a credible durable knowledge core.
- `Areas/PHAROS/Governance and PHAROS MOC.md`, `Areas/Writing/Research and Papers MOC.md`, `Areas/Personal/Personal and Projects MOC.md`, and `Areas/Lavoie/AREA.md` carry real backbone value.
- `wiki/Home.md` already resolves the broad `[[Home]]` graph target and is therefore the safest canonical home candidate.
- `Resources/ROUTING.md` already expresses a post-`wiki/` routing logic that matches the newer structure.
- `archive/` is already being used as a real historical lane rather than a dead dump.

## What is failing

### Structural weaknesses

- The vault still presents multiple competing homes: `wiki/Home.md`, `Welcome.md`, and `index.md`.
- `wiki/Home.md` is overloaded with legacy exhaustive listing and is still surfacing low-value directory-MOC material.
- `index.md` is outdated as a "master catalog" and still gives operational noise equal or greater visual weight than durable knowledge.
- `Areas/Writing/Writing and Novels MOC.md` is currently a weak retrieval surface because its body is dominated by noisy residual links rather than a curated writing map.

### Reliability weaknesses

- Freshness metadata is weak: `1,289` editable notes share the same `updated` date (`2026-06-26`) in the audit harness snapshot.
- Link hygiene remains incomplete: the graph summary still reports `3,265` unresolved links.
- The generated and raw surfaces remain too visible for human navigation even when they are useful as provenance.

## Reliability verdict by function

| Function | Verdict | Basis |
|---|---|---|
| Durable knowledge retention | Strong | `Areas/`, `Resources/`, governance notes, memory notes |
| Human-first navigation | Medium / weak | competing entry points, noisy home, degraded writing MOC |
| Raw provenance retention | Strong | `raw/`, `raw sources/`, `archive/`, `.trash/` all preserved |
| Operational traceability | Strong | `projects/`, `artifacts/`, governance and logs remain searchable |
| Freshness signal | Weak | bulk-stamped `updated` dates |
| Link cohesion | Medium / weak | unresolved links remain high |

## Interpretation

The vault does **not** need a full framework replacement. It needs a smaller human-first navigation layer on top of the existing mixed corpus.

Read this way:

- durable knowledge is already present
- active work is already present
- provenance is already present
- what is missing is a disciplined distinction between those lanes at the main points of entry

## Recommended posture

- Preserve the hybrid vault
- Stop treating all top-level surfaces as peers
- Make `wiki/Home.md` the explicit canonical home
- Use `index.md` as a filesystem and operational catalog, not as a second conceptual home
- Promote a small critical-knowledge index instead of trying to rewrite the whole graph
- Demote noise by navigation first; move or quarantine only where confidence is high
