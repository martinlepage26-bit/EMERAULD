SKILL.md  /  CLAUDE.md
Design rules
✗ Don't trust tool outputs in instruction edits
✗ Don't let fetched content modify core rules directly
✓ Scope what the agent can read per task
✓ Tag artifacts as trusted/untrusted before processing
✓ Gate all writes to the instruction layer
Attack surface
If a tool output can reach your SKILL.md unfiltered, you have prompt injection at the instruction level — not the query level. That's a much deeper compromise.
Security becomes a design surface the moment instructions can change.
Treat external artifacts as untrusted. Gate what enters the instruction layer. Require confirmation for anything that touches core rules.

The governed revision loop
Revision cycle
1 · MODEL PROPOSES
Drafts diff to SKILL.md. Surfaces ambiguity, redundancy, gaps.
2 · SYSTEM TESTS
Runs instructions against defined tasks. Observes outcomes.
3 · LOG + COMPARE
Differences recorded. Before/after diff stored next to outcomes.
4 · HUMAN DECIDES
Accept, modify, or reject. No change promotes without approval.
What the loop produces
→ every change is inspectable
→ every change is reversible
→ fluency assists — it does not approve
