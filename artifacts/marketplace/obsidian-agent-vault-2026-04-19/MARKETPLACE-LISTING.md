# Marketplace Listing Packet

## Title

Obsidian Agent Vault - Memory Layer for Claude Code and AI Coding Agents

## Short Description

A clean Obsidian starter vault that gives file-aware AI agents stable project memory, plus an optional local WSL runtime for buyers who want a query CLI and raw-note watcher.

## Full Description

Most AI coding sessions fail for a simple reason: the agent starts cold. You explain the project again, repeat decisions again, paste context again, and watch useful details disappear between sessions.

Obsidian Agent Vault fixes the layer underneath the model.

It gives you a clean file-native structure your agent can read: where standing context lives, where raw captures go, how useful notes become linked knowledge, and how future sessions find the work again.

It also includes an optional local runtime for WSL users, so the same folder can become a lightweight assistant shell with a setup script, a terminal query command, and a watcher that can auto-ingest `raw/` notes into LightRAG.

You get a ready-to-open Obsidian vault with:

- `CLAUDE.md` context loader for agent sessions, now framed as **Caelir - Context Guide**
- `START_HERE.md` first setup path
- `raw/`, `wiki/`, `skills/`, `archive/`, and `templates/` folders
- reusable hub templates for projects, people, concepts, decisions, and maps of content
- three named workflow guides: **Ilyris** for synthesis, **Ariun** for links, and **Mnara** for archive hygiene
- a buyer-run script for changing the guide names after purchase
- optional WSL runtime scripts for setup, local querying, and raw-note watching
- an optional Windows launcher for opening the runtime shell in the correct folder
- generic example notes showing the first retrieval loop

The promise is not magic memory. The promise is better structure. A file-aware agent can only use what it can find, interpret, and link. This vault gives it a working map.

## Best For

- solo founders using Claude Code, Cursor, Aider, or similar agents
- developers who keep repeating project context to AI tools
- researchers and operators managing messy notes across active projects
- WSL users who want a local-first agent scaffold without building a custom runtime from scratch
- teams that want a lightweight context layer before investing in heavier tooling

## Not For

- people expecting autonomous project management
- buyers who want a hosted knowledge-base product
- teams that need enterprise permissions, SSO, or managed infrastructure out of the box
- anyone who wants the tool to replace their own judgment

## Core Line

No heavy platform. No managed backend. Just a clean memory layer your agent can actually read, with an optional local runtime if you want one.
