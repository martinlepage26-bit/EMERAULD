# Your First Steps with the OpenAI API 
In this lesson, you are stepping into the role of a prototype developer at Praxis AI, our consulting firm that specializes in building advanced AI agents for other businesses. Think of this as your first hands-on mission in the world of applied AI development. Your project is for a client called Innovate Logistics. A major shipping and supply chain company. They need us to build an intelligent AI agent to help with their customer support. So as we move through this lesson, imagine yourself working directly with their team. But before we write a single line of AI logic, we need to get the foundation right. And yes, this is something we take very seriously at Praxis AI. As you'll see, there is a good reason for that. Not long ago, while consulting for a startup, we witnessed firsthand the consequences of leaked API keys. That incident led to a devastating financial loss for the company. Moments like that stay with you and they shape how we work. This is exactly why we start every project by focusing on three essential things. Keeping API keys safe, managing costs wisely and building resilience against rate limits. All three are crucial and in this lesson, you'll see why. Let's get started. Our first topic, the fundamentals and API keys and security. As you can see, I am on the OpenAI platform dashboard. You can sign in here using your Google account or your email. Here we navigate to the API keys section and this is where we generate a unique key. Everything starts here with your API key. Think of it as the master password to your account and its billing. The first rule is that it must always be treated as a secret. I'm generating one now and I'm writing it down somewhere safe. We'll need this key shortly when we begin coding. For security reasons, I have censored part of the key. Now let's move on the coding side and see how we'll use this. As you can see, I'm working inside VS Code and this is where we'll do our development. First, on the left side, you can see my project folder. I named it OpenAI Agent Demo, but you can name it whatever you like. Now I'm creating a .env file. Inside it, I'm adding a variable called OpenAIK and I'm passing the key I copied a moment ago. So, why did I do it this way? To keep it secret, we never put the key directly in our code. Instead, we use the industry standard method, an environment variable. We create a .env file in the root directory of our project to store the key safely. Next, I'm creating a .gitignore file in the same folder and inside it, I added my line .env. This single line prevents Git from ever tracking the file, ensuring your key is never accidentally exposed in a public repository. Now let's go back to the OpenAI page. Here, you can see the usage and billing pages. These pages show the per-token pricing. OpenAI does not charge per request. It charges per token. A token is simply a piece of a word. So, for a project like Innovate Logistics, which will process thousands of documents, we need to be precise. Now I'm switching back to the VS Code. I'm going to create a small token counting demo. I'm creating a new Python file and naming it token_counter_demo.py. We'll use this tik-token library to run a small example and see how many tokens a piece of text contains. I'm passing the code directly here. Let's walk through it. This small Python example shows how we can use OpenAI's official tik-token library to calculate the number of tokens in a given text. So what is this code doing? First, we import tik-token, which is the library OpenAI provides for tokenizing text the same way its models do. Next, we define the text we want to analyze. This is just a regular string, but it represents the kind of input we might send to a model. Then, using encoding_for_model, we load the exact tokenization rules used by the GPT-4 model. This step is important because different models can break text into tokens differently. Now that the encoding has broken our text down into tokens, we can simply use Python's len function to count how many tokens there are. This gives us the same token count the model itself would use, which is critical for estimating cost and staying within token limits. Finally, we print the result on the screen as the text contains X tokens. Now I'm running the code. In this example, the code shows we have around 10 tokens. That seems tiny, but if a capable model costs a certain amount, per million tokens, and Innovative Logistics processes 10,000 similar queries a day, that's over 3 million tokens per month. This certainly illustrates how cost can scale in the real time, and why we must measure tokens, not guess. And remember, this is only part of the total cost, because you also pay for the tokens generated in the model's response. Now let's continue. I'm going to show you a situation in VS Code that can easily produce an error. Here, I'll introduce a very, very simple test code that demonstrates how the API enforces rate limits. I'm passing the code here. First, we import the required libraries and load our environment variables. load_dotenv() reads the .env file, and us.getenv() retrieves our API key securely from the environment. Then we pass that key into openai.OpenAi() to create our client. This is the same setup you'll see in a real production application. No hard-coded secrets, and a clean, reusable structure. Next, we simulate a sudden traffic spike. In our real-world scenario, a blizzard hits a major distribution hub. Thousands of packages are delayed instantly, and instead of the usual 50 queries per minute, nearly 2,000 users try to check their package status at the same time. The loop here represents that search. Each iteration sends a tiny request using the GPT-4 model. The prompt is very simple, and the output token limit is low. We are not interested in the response itself. The goal is just to generate enough load to push the API to its limits. As the loop continues, the API eventually starts rejecting requests with a rate limit error. And now, let me actually run the script. And as you can see, after a short burst of requests, we immediately hit a rate limit error. The console fills with red error messages showing that the system can't handle the sudden surge. This is exactly what would happen if thousands of customers hit your system at the same time. A rate limit error. A basic script would simply crash, breaking the user experience. A professional application needs to recover from this automatically. To solve all these problems, security, costs, and resilience, you can build a single reusable token management system, the API Client class. It is designed to handle secure k-loading, precise cost calculation, and resilient request handling using the Modern Responses API.
