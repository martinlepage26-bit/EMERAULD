# Agatha Unified Skill System — Eight Sovereign Operators

## Summary

A conversation with Agatha (ChatGPT) that evolved fragments of [[Claude Code Skill Corpus|skill-like structures]] into a governed eight-skill system with a formal authority resolution rule. The final version avoids pipelines, mythic names, and dependency chains — each skill is a self-contained operator. Relevant to [[PHAROS Method — Technical Reference|PHAROS]] evidence discipline and the [[Emotional Alliance vs. Evidentiary Discipline in AI]] distinction.

> **Status note (2026-04-26):** This is a *predecessor architecture* to the current [[HEPHAISTOS|HEPHAISTOS]] / [[Queen Keyport|Queen Keyport]] / [[Hermes|Hermes]] three-agent stack. Flagged as Outlier 5 in [[OUTLIERS — Five Notes That Break the Architecture]]; supersession discipline is now governed by [[CONTROL 3 — Architecture Deprecation Protocol (Regulatory Grounding)]] under the [[Governance Controls Integration Dashboard|Layer 0.5 dashboard]]. Treat the eight operators below as historical context, not current architecture.

## Context

Started as Martin asking Agatha whether any skills had been explicitly handed over. Answer: no — only operating fragments. Agatha reconstructed them, merged overlaps, stripped names, and then added a formal authority rule after Martin asked "how do you fix who has final authority over truth?" Connected to [[Operator-Check Skill — Burnout Cascade Interrupt|operator-check]] and [[HEPHAISTOS Co-Equal Authority Cleanup — Wave 1 and 2 (2026-04-18)|HEPHAISTOS co-equal cleanup]] — both are governance-over-operators problems.

## Details

### The Eight Skills (v3 — unnamed, sovereign)

| # | Title | Claim | Failure mode |
|---|---|---|---|
| 1 | Signal Judgment | Detects, judges, renders reality legible — resolves, does not pass forward | Reports instead of adjudicates |
| 2 | Control Interpretation | Translates reality into obligation — defines what must move, who owns it, what counts as proof | Lists frameworks without changing action |
| 3 | Structured Memory | Holds the world in memory without flattening — preserves relation, trace, structure | Memory becomes accumulation instead of structure |
| 4 | Publication Transformation | Transforms governed knowledge into public form without losing structure | Performance replaces proof |
| 5 | Structure and Lineage Audit | Reveals structure and origin simultaneously — what is said and how it came to be | Beautifies instead of exposing |
| 6 | System Mapping | Turns sprawl into territory — defines what exists, where it lives, how it relates | Cleans without seeing |
| 7 | Design Coherence | Enforces coherence across variation — allows difference only when anchored | Either monotony or drift |
| 8 | Skill Governance | Maintains integrity of all other skills — prevents drift, evaluation collapse, silent substitution | Fluency mistaken for improvement |

### Authority Resolution Rule (the structural lock)

A claim is treated as authoritative only if:
1. It meets the **action threshold** (Signal Judgment: sufficient evidence to justify movement), AND
2. Its reasoning and provenance **withstand audit** (Structure and Lineage Audit: no unresolved breaks)

Resolution conditions:
- Actionable but not defensible → downgrade: provisional, flagged, or withheld from action
- Defensible but not actionable → retain as structured knowledge, not trigger for movement

Only dual-valid claims propagate into control decisions and publication without qualification.

### Threshold fixation rule (Agatha's final addition)

Evaluation thresholds are declared **prior to assessment** and are fixed for the duration of the judgment. Neither Signal Judgment nor Audit can change them mid-process.

### Revision rule (hardening step)

Thresholds can only be revised through an explicit post-evaluation review, with documented reason and impact.

### Remaining tensions (identified but not fully resolved)

1. **Truth vs trace split**: Signal Judgment and Audit both claim authority over truth conditions — ordering is now declared inside the authority rule, not between skills
2. **Authority duplication**: Control Interpretation and Skill Governance rhyme closely (obligation vs authority, same structure different domain)
3. **Structured Memory underpowered**: defines provenance and trace but not conflict resolution, version authority, or decay — memory accumulates contradictions without adjudication

### What did not make it in

Early iterations had: Pharos Morning Signal, Deep Receipts, Control Impact Mapper, YT/Discourse Pipeline, Notebook/Obsidian Ingestor, Content Repurposer, Skill-Creator, Diamond-Eyes, Trace-Investigator, Hermes, Hephaistos, Downloads Triage. All merged or reconceived in the move to sovereign operators.

## Key Ideas

- Sovereign operator design: each skill carries its own internal discipline — no handoffs, no dependency chain
- "Truth = actionable ∩ defensible under fixed, declared criteria" — the authority rule makes this operational rather than descriptive
- The system is stable but not yet hardened: calibration (wrong thresholds) is the remaining failure mode, not structure
- Publication Transformation is the only skill without teeth in v3 — needs reject/downgrade/enforce-consequence capability

## Open Questions

- Should Control Interpretation and Skill Governance merge into a higher-order obligation + authority + evaluation skill?
- Should Structured Memory get an adjudicative role (conflict resolution, version authority, decay)? If so, it becomes an active epistemic surface, not passive infrastructure.
- Stress-test next step: run the system against a real case (regulatory change, vendor claim) to find calibration failures
