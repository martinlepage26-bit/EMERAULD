# HELIX 3.0 Desktop Build Snapshot — Recursive Governor and Law 25 Control Surface (2026-05-11)

## Summary

Desktop captures show a concrete HELIX surface shift from protocol-centric `v2.5` toward a fuller governance product surface labeled `v2.6`/`HELIX3.0`. The key delta is not only multilingual probe orchestration, but integration of a reusable **recursion governor**, a **policy hierarchy**, and a **Law 25 compliance center** inside the same UI/logic envelope.

Verification report: `raw/intake-report-desktop-downloads-scan-2026-05-12.json`.

## What Changed vs Prior HELIX Desktop Corpus

- `HELIX PROBE v2.6` appears as the active probe component, with the same four-language track (EN/FR/ES/DE) and stronger governor instrumentation.
- Recursion control is split into a dedicated module (`Governor.ts`) with explicit termination conditions and compression/repetition tracking.
- Law 25 logic moved into first-class product components (`law25.ts`, `PolicyEngine.tsx`, `Dashboard.tsx`) rather than sitting only as market framing.
- UI shell now shows a governance platform posture (policy tree, impact assessment, HITL checkpoints, trace outcomes), not only a single-run test harness.

## Structural Signals

### 1) Probe remains PHAROS-framed

Pipeline still runs the MÖBIUS → TRANSIT → PHAROS progression with chain-of-scrutiny pressure and adversarial traps.

### 2) Governor is now explicit infrastructure

The recursion invariant appears as a named operational constant and triggers termination when repetition/invariant conditions are met.

### 3) Law 25 is operationalized in code

The build includes section-linked policy checks, section 12.1 transparency notice generation, and compliance score calculations. This indicates movement from "regulatory claim" to executable control logic.
