# Obsidian Agent Vault — Launch Kit

## Summary
A commercial launch packet for a low-friction digital product: a structured Obsidian vault sold as the "memory layer" for [[Claude Code Skill Corpus|Claude Code]] and other file-aware coding agents. The offer productizes the same vault discipline visible in [[Plugin Recommendations]] and the Obsidian/tooling layer documented in [[CLI-Anything — Agent Harness for Tool Integration]]. Part of [[Personal and Projects MOC]].

## Context
Source: `raw sources/obsidian_agent_vault_launch_kit_2026-04-14.md`. User-provided on April 14, 2026. The packet frames the core problem as repeated re-explanation across AI sessions and positions the solution not as a full RAG stack but as a structured vault that agents can actually navigate. It is both a product concept and an applied commercialization of the vault practice already operating inside [[Home]].

---

## Core Offer

**Product**: Obsidian Agent Vault

**Primary claim**: skip backend-heavy RAG infrastructure and instead sell a vault architecture that makes project memory legible to agents.

**What is being sold**
- Vault zip with four-layer architecture: raw, wiki, skills, archive
- Folder-level READMEs and hub-note templates
- `CLAUDE.md` starter for Claude Code
- `skill.md` template for reusable agent workflows
- 10-minute setup guide
- Bonus synthesis prompt for raw-to-wiki conversion

**Pricing ladder**
- Vault Template Pack — $49
- Guided Setup (async, 1 session) — $299
- Team Implementation (up to 5 seats, live) — $2,500

The ladder matters: this is one infrastructure product offered at three depths rather than three unrelated products.

---

## Positioning Logic

The product is explicitly anti-overbuild. The argument is not that retrieval is useless; it is that many builders are solving the wrong layer first. Instead of selling a full retrieval pipeline, the launch kit sells structure, orientation, and linking discipline.

That positioning connects directly to the vault logic already visible in [[Plugin Recommendations]] and the agent-facing tooling documented in [[CLI-Anything — Agent Harness for Tool Integration]]: the filesystem is already the shared substrate, so the most credible offer is to make that substrate legible rather than bolt on unnecessary infrastructure.

The strongest line in the packet is the conceptual inversion:

- not "build a smarter model"
- not "install a bigger memory system"
- but "build the memory layer"

## Audience And Boundary

**For**
- developers using Claude Code, Cursor, Aider, or other file-aware agents
- solo founders managing evolving project context
- researchers or technical operators maintaining complex note systems

**Not for**
- buyers expecting automation to replace thinking
- buyers who want a full managed backend instead of note infrastructure

This boundary is important. The packet refuses the "magic automation" frame and instead sells infrastructure. That keeps the promise aligned with what the product can actually do.

## Insights

- This is a commercialization of an already-practiced method, not an invented product detached from real use. That gives the offer more credibility than a generic "AI productivity" template.
- The phrase "no RAG, no database, no overhead" is a positioning move against complexity creep. It differentiates the product by subtraction rather than by feature inflation.
- The most persuasive demo moment is not the folder walkthrough but the live raw-to-wiki conversion followed by retrieval. That is the proof that the vault changes agent behavior.
- The $49 / $299 / $2,500 ladder creates a clean path from solo buyer to team implementation without changing the core product identity.
