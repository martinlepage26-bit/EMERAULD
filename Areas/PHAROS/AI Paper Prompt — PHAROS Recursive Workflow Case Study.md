# AI Paper Prompt — PHAROS Recursive Workflow Case Study

## Summary

A structured ChatGPT prompt designed to produce a serious scholarly paper about how AI was used across the [[PHAROS]] project. The prompt governs the paper's chronology, method rules, claim boundaries, section structure, and citation discipline. It references [[PHAROS AI Lineage — Source of Truth]] as the backbone and [[PHAROS Cross-AI Strategy Matrix]] as the role-function aid.

## Context

This is the prompt artifact that operationalizes the PHAROS AI workflow narrative as a publishable academic output. It connects the raw chronological and strategic documentation ([[PHAROS AI Lineage — Source of Truth]], [[PHAROS Cross-AI Strategy Matrix]]) to the [[AI Society Manuscript — From AI Anxiety to Recursive Governance]] paper-building project. The applied case from [[The Blind Leading the Automated — AI Governance Failure Case Study]] is explicitly integrated as the implementation stress-test section.

## Details

**Paper framing — four overlapping genres:**
- Autoethnographic method reflection
- Human-AI workflow case study
- Governance and authorship analysis
- Platform and tooling history

**Core requirement (non-negotiable):**
- Do not flatten the chronology
- Do not overclaim what the archive proves
- Separate direct evidence, supported inference, and unverified steps
- Treat Extended Thinking use as authoritative (do not infer Instant mode from folder labels)
- Treat cross-use of AIs as deliberate strategy when archive and user corrections support it

**Chronology backbone (12 steps):**
Agatha → Voice Operator 1 → Governess Agatha → Henry → Reviewer #2 injection → Dottie → Mobius/SuperPower/desktop → skills escalation → MASTERskill → skill-architect → Codex/Claude via WSL → trace-investigator

**Method rules (recursive-governance reading):**
1. Identify source-bearing vs. generated/editorial artifacts
2. Build evidence hierarchy
3. Distinguish direct evidence from supported inference
4. Identify where outputs re-entered the workflow as governing inputs
5. Name major shifts in control, review, voice, and execution capacity
6. Identify when operator logic becomes skill logic and when skill logic becomes cross-agent implementation
7. Turn recurring failures into governance lessons

**Claim boundary rules:**
- Do not claim the project "solved AI governance"
- Do not collapse one vivid workflow into a general law
- If chronology step is only partly documented, say so
- If memory and archive diverge, name the divergence

**Required output structure:**
1. Proposed title
2. 200–300 word abstract
3. Section-by-section outline
4. Full draft paper
5. Evidence-boundary note at the end distinguishing direct, supported, and recollection-dependent points

**Named consequence domains for the paper:**
authorship, auditability, workflow control, legitimacy, review pressure, implementation, observability

**Citation rules:** Use only sources present in the uploaded packet or explicitly provided by the user. Mark missing citations as placeholders rather than inventing them.

## Key Ideas

- The prompt is itself a governed artifact: it applies the same evidence discipline it asks the paper to produce
- The cross-AI strategy requirement is baked into the prompt — prevents the paper from narrating the workflow as single-assistant accumulation
- The website-building case ([[The Blind Leading the Automated — AI Governance Failure Case Study]]) is required as the applied governance stress test, not optional illustration
