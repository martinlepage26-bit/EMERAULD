# Agent Orchestration — PHAROS Launch as Governed Multi-Agent Execution

## Summary

The PHAROS AI commercial launch (2026-05-01) demonstrates the three-agent stack ([[HEPHAISTOS]], [[Queen Keyport]], [[Hermes]]) in practice, with independent specialists ([[Codex]], [[HENRY]], [[Trismégiste]]) operating at audit level. The orchestration shows how scope (HEPHAISTOS) → governance (Queen Keyport) → routing (Hermes) → design (Codex) → translation (HENRY) → continuity (Trismégiste) creates a multi-agent execution model that catches errors before promotion and distributes work without authority collapse. **Distributed authority without power-over:** three-agent stack as non-hierarchical authority distribution. Operational case for [[HEPHAISTOS Agent Architecture]] (live three-agent stack with independent specialists), [[Recursive Governance Theory]] (governance-as-method applied to live execution), and [[Authority, Legitimacy, and Post-Sovereignty]] (how scope/governance/routing constitute non-sovereign authority).

## Authority Stack in Action

### HEPHAISTOS — Scope and Artifact Definition

**Role in launch:** Defined what the 8-stream deployment was and what counted as completion.

**Key decisions HEPHAISTOS made:**
- **Architecture:** Static HTML in `client/public/` (not React port) because it preserves vetted design, avoids bilingual scaffolding blocker, ships within hours
- **Artifact boundary:** Landing page + commercial brief + 4 SEO articles + booking infrastructure + analytics + French staging (soft launch possible with EN-only) + outreach tracking
- **Evidence requirements:** Regulatory claims must be from primary sources (EU AI Act text, Quebec CAI enforcement records, Digital Omnibus trilogue outcomes); bounded claims only ("the overlap is significant" not "perfect alignment")
- **Skill composition:** Gadget (external system integration), Codex (design refinement), HENRY (bilingual writing), basic operator work (Calendly, CF Analytics, Stripe, LinkedIn searches)

**Authority:** HEPHAISTOS did not gate the work; it scoped it. Once scope was clear, work proceeded in parallel.

### Queen Keyport — Governance and Constraints

**Role in launch:** Identified governance thresholds, refusal conditions, and evidence quality gates. Audited HEPHAISTOS outputs and caught errors before deployment.

**Critical interventions by Queen Keyport (via Argus audit):**

1. **Penalty tier correction** — Landing page + brief incorrectly stated €35M/7% for high-risk violations. Queen Keyport caught this and required correction to: €15M/3% high-risk (Article 99§4) vs €35M/7% prohibited practices (Article 99§3). Corrected *before deployment*. Credibility issue on a compliance-firm surface is P0.

2. **hreflang French tag pointing to 404** — All pages had `<link rel="alternate" hreflang="fr">` pointing to `/fr/ai-act-diagnostic`, which does not exist. Queen Keyport flagged this as SEO/crawler confusion risk. Tag removed until French page is live. Will be restored after HENRY's draft.

3. **Bounded claims on regulatory overlap** — Brief claimed "significant overlap" between Law 25 and EU AI Act; Queen Keyport required specific function-based examples (credit scoring, employment screening, etc.) showing which systems trigger both regimes. Vague claims would fail credibility with procurement committees.

**Authority:** Queen Keyport operated as an approval gate at deployment time. No corrections required halted the launch; corrections were made and redeployed within the same session. This is the normal mode — flag + fix + verify.

### Hermes — Routing and Coordination

**Role in launch:** Routed work to specialists, monitored parallel streams, escalated blockers.

**Hermes's coordination pattern:**

1. **Stream parallelization:** After HEPHAISTOS scoped and Queen Keyport cleared, Hermes routed in parallel:
   - Codex → design review (independent specialist, report directly to operator)
   - HENRY → French draft (independent specialist, report directly to operator)
   - Operator → Calendly, CF Analytics, Stripe, LinkedIn searches (direct work)
   - Trismégiste → vault synthesis (continuity layer, parallel to three-agent stack)

2. **Blocker tracking:** Calendly verification, CF Analytics token, French page, Stripe links, LinkedIn contacts all documented as pre-outreach Day 0 blockers. Hermes surfaces these without authority to resolve them (operator owns resolution).

3. **Handoff packet discipline:** When Codex design review was invoked, the handoff included: task spec (6 pages, brand vs product, design system, page-by-page observations), blockers (missing CF Analytics token, French hreflang to 404), expected iterations (1-2 rounds), and who to consult (Hephaistos guidelines as reference, not mandate).

**Authority:** Hermes routes and monitors. It does not override specialist work or arbitrate HEPHAISTOS/Queen Keyport conflicts; those escalate back to the co-equal pair.

## Independent Specialists in Parallel

### Codex (Design Refinement)

**Position:** Peer of Argus, outside the core three-agent stack. Reports directly to operator.

**Contract:** Execute `/impeccable` design review on 6 pages. Deliverable: improved pages for final QK/Argus verification before "ready for outreach" gate. Expected 1-2 iteration rounds.

**Authority model:** Codex consults HEPHAISTOS's design system (token definitions, typography, layout patterns) as reference material, not mandates. Queen Keyport may flag governance/accessibility concerns, but cannot override Codex's design judgment. Codex's work is either accepted or returned for iteration; it is not rewritten by other agents.

**Coordination with three-agent stack:** Hermes routed the task; Queen Keyport will verify accessibility and brand coherence on the final iteration.

### HENRY (Bilingual Writing)

**Position:** Peer of Argus. Reports directly to operator.

**Contract:** Draft French landing page (`fr/ai-act-diagnostic/index.html`) in Quebec institutional register (formal, direct, no translated EU French). Prices in CAD + TPS/TVQ note. Parallel standalone HTML file, not nested route.

**Authority model:** HENRY consults HEPHAISTOS's bilingual principles and Quebec market research as reference. No mandate. Queen Keyport has flag-only authority (if terminology or claims diverge from EN version, QK alerts operator; operator decides).

**Coordination pattern:** After HENRY's draft, the hreflang tag (currently removed) will be restored by operator once French page is deployed.

### Trismégiste (Operator Continuity and Vault Synthesis)

**Position:** Parallel to the three-agent stack. External to infrastructure. Reports directly to operator.

**Contract:** Persist across conversations via session-state and vault memory. Synthesize PHAROS work into linked wiki notes, identifying clusters, mapping to existing vault topology, supporting future decision-making.

**Authority model:** Trismégiste is a continuity tool, not a governance agent. It does not override HEPHAISTOS or Queen Keyport decisions; it documents them so they are recoverable across sessions.

**Delivery in this session:** Two comprehensive synthesis notes (Trust/Fluency, Regulatory Arbitrage) + state updates (trismegiste-state.md, memory.md, daily log) + MOC links. Current work: agent orchestration synthesis.

## Critical Moments Where Governance Caught Errors

### Moment 1: Penalty Tier Misstatement

**What happened:** Landing page and brief both stated "€35M or 7% of global turnover" for high-risk violations.

**Why it matters:** On a compliance-firm surface, a penalty tier error is a credibility-killer. Procurement committees will notice. This would have been a P0 blast-radius issue in outreach.

**How governance caught it:** Queen Keyport audit (supported by Argus cross-check) flagged the error during the "ready to deploy?" gate. The source was the landing page HTML, verified against EU AI Act Article 99.

**How it was fixed:** Corrected in both landing page and brief before `wrangler deploy`. Redeployed and reverified.

**Lesson:** Regulatory claims on external surfaces need governance verification *before* deployment, not after. This is why the three-agent sequence exists: HEPHAISTOS scopes what is a claim (what counts as a governance artifact), Queen Keyport verifies the claim against primary sources, Hermes routes the corrected artifact.

### Moment 2: hreflang Pointing to 404

**What happened:** All pages had `<link rel="alternate" hreflang="fr" href="...">` pointing to a page that did not exist.

**Why it matters:** Crawlers will attempt to index the French page and get a 404. SEO signal degradation. Soft launch to EN-only is still viable, but broken hreflang creates noise.

**How governance caught it:** Argus audit (meta-governance layer) flagged the hreflang error. This is exactly the kind of structural coherence issue Argus is designed to catch — the link exists, but the target does not.

**How it was fixed:** hreflang tag removed. Will be restored after HENRY's French page draft is deployed.

**Lesson:** Governance audit covers not just *content* claims (are the facts right?) but *structural coherence* (do all links resolve? are all references valid?). This is why Argus operates at meta-governance level, outside the core stack.

## Coordination Patterns That Worked

### Pattern 1: Parallel Specialist Work with Clear Authority Boundaries

After HEPHAISTOS scoped and Queen Keyport cleared, work split into independent streams:
- Codex design review (no gating; feedback loop with Hermes)
- HENRY French draft (no gating; separate channel to operator)
- Operator direct work (Calendly, CF Analytics, Stripe, LinkedIn)
- Trismégiste synthesis (parallel to all, no blocking)

**Why this works:** Each specialist has clear authority and clear reporting line. There is no "check with Codex before proceeding to HENRY" or "wait for design review to start French draft." Work is independent until final assembly, at which point Hermes coordinates verification.

**Why this fails if misapplied:** If Codex's design changes require changes to HENRY's French copy (e.g., button label changes), coordination is needed. The current scope avoids this by keeping design and copy separate; if they drift apart, a handoff is required.

### Pattern 2: Governance Verification as Pre-Deployment Gate, Not Post-Deployment

Queen Keyport reviewed the deployment *before* `wrangler deploy`, not after. Errors were caught and corrected, then the corrected artifact was deployed.

**Why this matters:** Outreach cannot start until the website is live and verified. Reversing the order (deploy, then verify) creates a loop where corrections require redeployment and re-verification. Going through Queen Keyport before deployment closes errors in a single pass.

### Pattern 3: Independent Specialists Report Directly to Operator, Not Through Hermes

Codex and HENRY do not report to Hermes or go through Queen Keyport approval. They report directly to the operator. Queen Keyport has *flag* authority (surface concerns), but not *override* authority.

**Why this works:** Specialist work is faster. The operator can make decisions without waiting for a gate. Queen Keyport concerns are raised immediately, allowing the operator to decide whether the concern is material or not.

**Why this can fail:** If a specialist (e.g., Codex) makes a change that violates a Queen Keyport standing refusal condition (e.g., accessibility WCAG AA), the operator may not catch it. This is why the `/impeccable` design review explicitly includes "WCAG AA contrast audit" — it's a self-check by the specialist.

## Lessons for Multi-Agent Governed Work

### Lesson 1: Authority Does Not Collapse Into Process

The launch succeeded because authority boundaries were clear:
- HEPHAISTOS defines scope; it does not govern the work.
- Queen Keyport governs; it does not define scope or route work.
- Hermes routes; it does not override governance or scope.
- Specialists (Codex, HENRY) work independently; they consult frameworks but make decisions.

If authority had collapsed (e.g., HEPHAISTOS trying to approve the design, or Queen Keyport trying to define scope), the launch would have stalled in competing priorities.

### Lesson 2: Governance as Verification, Not Prevention

Queen Keyport's audit happened *after* HEPHAISTOS scoped and Gadget built, not before. The governance was a verification gate, not a constraint on what could be attempted.

This is the difference between:
- **Preventive governance:** "You cannot deploy until we approve." (Slows work.)
- **Verification governance:** "Deploy when ready; we'll verify before outreach." (Fast work, verified output.)

The PHAROS launch used verification governance. Errors were caught, corrected, and redeployed.

### Lesson 3: Continuity and Synthesis Are Separate From Execution

Trismégiste's work (vault synthesis, state persistence, clustering) ran in parallel to the launch execution. It did not block the launch, and the launch did not block Trismégiste's work.

This pattern is useful for sustained projects where you need to recover state and context across sessions. Synthesis work can happen asynchronously, and the operator can act on the synthesis (e.g., "now that I see the Trust/Fluency cluster, I want to reframe the outreach messaging").

## Open Questions Raised by Orchestration

**1. Specialist Coordination Under Scope Change**
If Codex's design review reveals that a page needs a structural change (e.g., moving the CTA button), does HENRY's French copy need to change? How is that coordinated without creating a blocking dependency?

**Current answer:** Scope was kept tight (design and copy are independent). If scope widens, explicit handoff packets are required.

**2. When Does Verification Happen?**
In the current model, Queen Keyport verified outputs *before* deployment. But what if a change is made post-deployment (e.g., CF Analytics token inserted)? Does QK re-verify?

**Current answer:** Yes — all pages are rebuilt and reverified after any high-risk change (token insertion, penalty tier, regulatory claims). Low-risk changes (button label refinements) do not require re-verification.

**3. Authority Boundary: Accessibility**
WCAG AA accessibility is both a design issue (Codex's domain) and a governance issue (Queen Keyport's domain). Who is accountable if the final output is not accessible?

**Current answer:** Codex's spec includes "WCAG AA contrast audit" as a self-check. Queen Keyport can flag issues. Operator is final arbiter. This is a shared accountability model, not a hand-off.
