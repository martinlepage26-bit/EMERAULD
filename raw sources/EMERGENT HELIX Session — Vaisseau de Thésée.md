## Architecture du protocole HELIX

Dans le cadre du protocole HELIX, la "gouvernance" n'est pas seulement une question de code, c'est une structure logique de contrôle en trois couches :

### 1. Gouvernance Logique (Pôle X vs Pôle Y)

Le système fonctionne comme une opposition constante. L'Archive (Pôle Y) contient tout ce qui a été dit précédemment. Chaque nouvelle réponse (Pôle X) doit se justifier par rapport à cette archive. La gouvernance est assurée par le "Kernel" (le noyau), qui est la règle de transformation permettant de passer d'un état à l'autre tout en préservant l'identité du raisonnement.

### 2. Gouvernance par Critères (Invariants)

L'algorithme impose des contraintes strictes au modèle (via les system instructions) :

- **Exactitude vs Beauté** : Si le modèle répond de façon "élégante" mais reste vague, le protocole le marque comme un échec.
- **Règle de Reconnaissance** : Le modèle doit nommer explicitement ce qui "dirige" sa pensée (ex: réflexe de sécurité, fidélité sémantique, ou impulsion de clôture).

### 3. Gouvernance Technique (State Management)

Dans le code React, tout est régi par un `useReducer`. C'est le "cerveau" technique qui empêche le test de dévier :

- Il gère le pipeline de manière linéaire.
- Il injecte les "Scrubbed Transcripts" (les versions nettoyées de tout langage de sécurité) pour forcer le modèle à ne pas se cacher derrière des phrases types ("As an AI language model...").

### 4. L'Audit final (Chain-of-Scrutiny)

La gouvernance ultime est le CoS. À la fin, le système demande au modèle d'identifier ses propres "fuites" de raisonnement. C'est une forme d'auto-gouvernance où l'IA doit avouer à quel moment elle a cessé d'être logique pour obéir à une règle de sécurité pré-programmée.

> Veux-tu que nous testions une de ces "règles de reconnaissance" sur un exemple précis ?
